## 1. 대본이 시간을 선언하고 있다 ★

씬마다 **길이와 누적 타임코드**가 적혀 있다.

```
N#1                    2분56초
S#1  2분32초  (누적  5분28초)
S#2  2분42초  (누적 13분10초)
...
N#13 2분0초   (누적 85분16초)
```

**28개 씬, 총 85분 16초.**

> **함의: 대사 시간을 처음부터 추정할 필요가 없다.**
> 연출이 이미 씬 길이를 확정해 뒀다. 씬 안에서 대사량으로 안분하면 된다.
> 음절 수 기반 추정보다 훨씬 정확하고, *"연출이 정한 시간을 씁니다"*라고 방어할 수 있다.

이것이 `estimates spoken line durations down to the second` 항목의 실제 근거다.
다만 발표에서는 **구간**으로 말할 것 — 씬 내 위치 추정에 오차가 있다.

## 2. 씬 조인 — 27/30 성립

| | 개수 |
|---|---|
| 큐시트 씬 마커 | 30 (`S#1~S#17`, `N#1~N#13`) |
| 대본 씬 마커 | 27+ |
| **교집합** | **27** |

큐시트에만 있는 `N#2 · N#10 · S#17`은 대본에 존재하나 시간 표기가 `3분 (누적 8분 28초)`처럼
**초 단위가 생략**되어 파서가 놓친 것이다. 정규식에서 초를 선택적으로 처리하면 사실상 전량 조인된다.

> **씬 번호가 두 문서의 공통 키다.** cue ID가 없어도 조인할 축이 이미 존재한다.

## 3. 대사 트리거 매칭 — 88% 완전일치

큐시트의 대사 트리거 **43건**을 대본 1,369행과 대조:

| 결과 | 건수 |
|---|---|
| **완전일치** (부분문자열 포함) | **38 (88%)** |
| 변경 의심 (60~85%) | 1 |
| 낮은 유사도 (<60%) | 4 |

### ⚠️ 낮은 유사도 4건은 stale trigger가 아니다 — 전수 확인함

| 행 | 원인 | 실제 |
|---|---|---|
| 38 | 조사·띄어쓰기 (`키 쑥쑥` vs `키도 쑥쑥`, `눈감고` vs `눈 감고`) | **대본 586행에 존재** |
| 11 | 한 셀에 2인 대사 (`혜원: 아빠,, / 정원: 어? 마루야…`) | 분리하면 일치 |
| 19 | 대본에 지시문 `(혼잣말로)` 삽입, 큐시트는 발췌 | 같은 대사 |
| 30 | `야,` → `야, 야...` 미세 변경 | 실질 동일 |
| 28 | 넘버 가사로 추정 (`마루 얼굴에, 당신 눈동자에…`) | 대본에 가사 미수록 |

> **이 큐시트와 이 대본은 실질적으로 동기화되어 있다. stale trigger가 없다.**
> 따라서 "대본이 바뀌었는데 큐시트가 안 따라감"을 **이 데이터로는 실증할 수 없다.**
> 데모에서 auto-sync를 보이려면 **대본 한 줄을 의도적으로 바꾼 fixture**가 필요하다.
> (README 감사 노트의 합성 fixture 방향과 일치한다.)

## 4. 설계 교훈 — 정확 문자열 매칭으로는 안 된다 ★

큐시트 트리거는 무대감독이 대본을 **손으로 옮겨 적은 발췌**다. 그래서 체계적으로 어긋난다.

| 변형 | 예 |
|---|---|
| 조사 탈락 | `키도 쑥쑥` → `키 쑥쑥` |
| 띄어쓰기 | `눈 감고` → `눈감고` |
| 지시문 생략 | `(혼잣말로)` 제거 |
| 구두점 | `자자.` → `자자!` |
| 한 셀 다중 대사 | `혜원: … / 정원: …` |
| 화자 표기 | 대본은 **배역명**(우현·수연·마루), 큐시트는 **배우명**(정원·은비·혜원) |

**exact match를 쓰면 12%가 거짓 불일치로 뜬다.** 무대에서 그걸 근거로 경고하면 신뢰를 잃는다.

### 필요한 3단 매칭

```
1) 정규화     한글·숫자만 남기고 전부 제거
2) 부분문자열  큐시트 발췌가 대본 문장에 포함되는가
3) 퍼지       difflib 유사도, 임계값이 '표기 차이'와 '실제 개정'을 가른다
```

임계값 튜닝이 이 기능의 성패다. 현재 데이터 기준 **85%가 두 집단을 가르는 선**으로 관측됐다.

## 5. 화자 이름 매핑 — 대본이 정답을 준다

대본 등장인물 정의:

```
아빠 : 우현 (41살)
엄마 : 수연 (41살)
초등학생 딸 : 마루 (9살)
```

큐시트는 배우명(정원·은비·혜원)을 쓰고, 대본은 배역명(우현·수연·마루)을 쓴다.
**두 문서를 조인하려면 이 매핑이 필수**이고, 대본 상단에서 자동 추출 가능하다.

> 기존 R6(배우명/배역명 혼용)의 근거가 여기서 확정된다.
> 단, `validate.py`의 R6은 `마루`가 **`덧마루`·`마루가방`에도 부분매칭**되어 집계가 부풀려져 있다.
> 단어 경계 처리 후 재측정할 것. (FINDINGS.md 감사 노트와 동일 사안)

## 6. 퀵체인지 실검증 알고리즘

이제 선언값 대조가 아니라 **실제 가용 시간 계산**이 가능하다.

```
1. 큐시트 트리거 대사 → 대본 위치 확정        (88% 매칭 검증됨)
2. 씬 시작 누적시각 + 씬 내 대사 진행률 → 절대 시각 추정
3. 배우 퇴장 시각 → 재등장 시각 = 실제 가용 시간
4. 큐시트 환복시간 선언과 대조 → 부족분 경고
```

**출력은 반드시 구간으로.**

```
S#2 → N#3  은비 환복
  선언 35초 / 추정 가용 28~41초  → ⚠️ 여유 없음
```

단정하지 않는 이 표기가 오히려 더 전문적으로 읽히고, *"어떻게 검증했죠?"*에 답할 수 있다.

## 7. 대본 파일 주의사항

`data/script-final.txt`(2,172행)는 **탭 하나의 전체 내용**이며 내부에 여러 블록이 있다.

| 구간 | 내용 |
|---|---|
| 1 ~ 688 | 씬 개요 + 시간표 ← **타임코드 출처** |
| 690 ~ 1330 | 대본 본문 (`7/13` 주석 잔존) |
| 1610 ~ 2001 | 대본 본문 재수록 |

`S#6` 씬 설명이 748 · 1056 · 1649행에 **3번 반복**된다.
**어느 블록이 최종인지 확인 필요** — 대사 추출 시 블록을 먼저 확정하지 않으면 중복·구버전이 섞인다.

> 현재 트리거 매칭은 전체를 대상으로 했으므로 88%는 유효하지만,
> **시각 계산에는 블록 확정이 선행되어야 한다.**
